# SECTION 1 — Product Understanding

## Product Vision
ActionLens AI is an **AI Decision Intelligence Platform** that transforms official climate and disaster early warnings into personalized, role-specific action recommendations. It answers one question: **"What should I do now?"** — not "here is a weather alert."

## Mission
To ensure that every person affected by a climate or humanitarian crisis — farmer, government official, health worker, or citizen — receives a clear, prioritized, actionable response plan generated by AI before, during, and after the event.

## Target Audience
| Role | Primary Need |
|---|---|
| Government Officials | Coordinate response, deploy resources, make policy decisions |
| Humanitarian Organizations (NGOs) | Field resource deployment, logistics, beneficiary tracking |
| Emergency Responders | Real-time situational awareness, route safety, triage |
| Farmers | Protect crops, livestock, livelihoods |
| Health Workers | Disease surveillance, medical supply readiness |
| Community Members | Personal safety, family preparedness, local reporting |

## User Roles (System)
- `government` — elevated analytics, deployment tools, briefing generation
- `ngo` — resource allocation, community report verification
- `responder` — real-time map, route access, incident reporting
- `farmer` — agricultural risk, crop/livestock guidance
- `health_worker` — epidemiological alerts, medical supply tracking
- `citizen` — personal safety, community reporting, basic resources

## Core Value Proposition
1. **Personalized action plans** — same flood event, six different role-specific responses
2. **Explainable AI** — every recommendation shows its evidence chain ("Why?")
3. **Action Impact Simulator** — compare scenarios before committing ("What if we wait 24h?")
4. **Recommendation Timeline** — NOW / 6h / 24h / 72h prioritized action sequences
5. **Community intelligence** — AI-verified field reports feed the risk model

## Problems Solved
- Early warning systems generate alerts that nobody knows how to act on
- All roles receive identical information despite needing different decisions
- Decision-makers have no way to model the consequences of their choices before acting
- Community ground truth is collected in silos (WhatsApp groups, phone calls)
- AI recommendations are black boxes — trust is low

## Success Metrics (MVP)
- Time-to-action: <5 minutes from login to first actionable recommendation
- Recommendation confidence score displayed on every card
- Community report verified by AI within 60 seconds
- Action Impact Simulator responding within 8 seconds
- Application loads on 3G in under 4 seconds

## MVP Goal
A fully functional, beautifully designed web application that demonstrates the complete AI-powered decision intelligence loop: ingest risk data → generate personalized recommendations → display explainability → simulate action impact → collect community reports → generate briefings. All powered by OpenAI with Supabase as the data layer.

# SECTION 4 — User Journey

## Journey 1 — Registration & Onboarding
1. Land on `/` (Landing) → click "Get Started"
2. `/register` → email, password, name, agree to terms
3. Email verification (Supabase) → click link → redirected to `/onboarding`
4. `/onboarding/welcome` → "Welcome to ActionLens AI"
5. `/onboarding/role` → select role (farmer/government/ngo/health/responder/citizen)
6. `/onboarding/location` → select country → region → district
7. `/onboarding/interests` → select risk categories (flood, drought, disease, agriculture)
8. `/onboarding/notifications` → enable email, SMS phone number, WhatsApp
9. `/onboarding/complete` → animated completion screen → redirect to `/dashboard`

## Journey 2 — Daily Dashboard Check
1. Login → `/dashboard`
2. See greeting ("Good morning, Amara") + current risk level
3. AI Recommendation Card loads with top 3 actions + confidence score
4. Tap "View Full Plan" → `/recommendations`
5. Review timeline (NOW / 6h / 24h / 72h)
6. Tap "Why?" on any recommendation → Explainability Panel slides in
7. Mark action as "Done" → confirmation logged to Supabase
8. Return to dashboard → AI adapts based on completed actions

## Journey 3 — Using the Action Impact Simulator
1. From `/recommendations`, click "Simulate Impact"
2. Input scenario: "What if we delay shelter opening by 24 hours?"
3. FastAPI + OpenAI processes scenario → returns consequence model
4. Side-by-side comparison: Act Now vs. Wait 24h
5. Government official copies briefing → shares with team

## Journey 4 — Risk Map Exploration
1. Navigate to `/map`
2. Map loads centered on user's region
3. Toggle layers: Flood ON → colored risk overlays appear
4. Toggle Community Reports ON → pins with thumbnails appear
5. Click a pin → report detail sidebar opens
6. Click shelter icon → shelter capacity and distance shown

## Journey 5 — Submitting a Community Report
1. `/community` → tap "Report an Incident"
2. Enter description, select category, set severity
3. Grant location permission → map pin placed
4. Upload photo (optional)
5. Submit → AI immediately scores confidence
6. Report appears on map with "Pending Verification" badge
7. Within 60s → AI updates badge to "AI Verified: 94%"

## Journey 6 — AI Assistant Interaction
1. Navigate to `/assistant`
2. Type: "Generate emergency briefing for Kisumu County"
3. AI generates structured briefing with: situation summary, recommended actions, resource needs, contact points
4. User clicks "Copy" or "Download PDF"
5. Next query: "What should health workers do in this flood zone?"
6. AI returns role-specific health recommendations

## Journey 7 — Receiving and Acting on Alerts
1. Push notification arrives (email or in-app)
2. User clicks → deep link to `/alerts/:id`
3. Alert detail page: source, severity, affected area, AI-generated actions
4. Tap "Take Action" → adds action to dashboard timeline
5. Action marked complete → contributes to analytics

# SECTION 8 — Page Specifications

## 8.1 Dashboard (`/dashboard`)

**Purpose**: The command center. Answers "What should I do now?" immediately on load.

**Components**: `RiskLevelCard`, `AIRecommendationCard`, `ActionTimeline`, `MapPreview`, `AlertFeed`, `QuickStats`, `CommunityActivity`, `WeatherSnapshot`

**Features**:
- Greeting: "Good morning, {name}" with local time
- Current Risk Level: color-coded badge (CRITICAL/HIGH/MODERATE/LOW/SAFE)
- AI Recommendation Card (hero component) — top 3 actions with confidence score
- "View Full Plan" → navigates to `/recommendations`
- Interactive map preview (Google Maps embed, 400px tall) with risk overlay
- Recent Alerts feed (last 3)
- Action Timeline — scrollable horizontal NOW/6h/24h/72h
- Community Reports count + latest 2 entries
- Quick Stats: communities protected, warnings issued (animated counters)

**Data Required**:
- `users` table: name, role, location
- `recommendations` table: latest for user's region + role
- `alerts` table: active alerts for user's region
- `community_reports` table: last 5 in user's region
- External: OpenWeatherMap snapshot for user's coordinates

**Loading State**: Full-page skeleton with animated shimmer
**Empty State**: "No active risks. We'll notify you immediately if conditions change."
**Error State**: "Unable to fetch latest data. Showing last verified information."
**Permissions**: Authenticated users only. Role affects recommendation content.

## 8.2 AI Recommendations (`/recommendations`)

**Purpose**: Full personalized action plan with timeline, confidence scores, explainability, and impact simulation.

**Components**: `RecommendationCard`, `ExplainabilityPanel`, `ActionTimeline`, `ConfidenceScore`, `ImpactSimulatorButton`, `EvidenceChain`, `ActionConfirmButton`

**Features**:
- Sorted list of recommendations by priority (CRITICAL → LOW)
- Each card shows: action, priority, time sensitivity, confidence score (%), expected impact
- "Why?" button → slides in `ExplainabilityPanel` from the right
- Explainability Panel: visual evidence chain with icons (Rain probability, Soil saturation, ICPAC alert, Historical data, Satellite data)
- "Simulate Impact" button → opens `ImpactSimulatorModal`
- "Mark as Done" → updates action status in Supabase; dashboard adapts
- Recommendation Timeline visualization (animated horizontal flow)
- Filter by: time horizon, priority, category

**Data Flow**: `POST /api/recommendations` → Next.js Route Handler → FastAPI `/recommendations` → OpenAI GPT-4o with Structured Outputs → returns typed `Recommendation[]` → cached in TanStack Query for 30 min

**Loading State**: 3 skeleton recommendation cards
**Empty State**: "You're all caught up. No active recommendations for your region."
**Permissions**: Role determines recommendation set. Government users see additional policy-level actions.

## 8.4 AI Assistant (`/assistant`)

**Purpose**: Mission Control interface — natural language AI for briefings, Q&A, report summaries, SMS generation.

**Components**: `ChatInterface`, `MessageBubble`, `SuggestedActions`, `BriefingOutput`, `CopyButton`, `StreamingIndicator`

**Features**:
- Clean chat interface (NOT ChatGPT-clone — more like Notion AI sidebar)
- Suggested prompts displayed on empty state:
  - "Generate emergency briefing"
  - "What should health workers do?"
  - "Which villages are highest risk?"
  - "Draft SMS alert for flood in [region]"
- Streaming response (OpenAI streaming API)
- Structured outputs when query matches briefing/SMS format
- "Copy" and "Download" actions on structured outputs
- Conversation history stored in Supabase (`conversations` table)
- Context: user's role, region, and current active alerts injected into system prompt

**Data Flow**: User message → `POST /api/assistant` → Next.js Route Handler → FastAPI `/assistant` → OpenAI with RAG context + role system prompt → streamed back to client

## 8.5 Community Reports (`/community`)

**Purpose**: Crowdsourced intelligence layer — submit, browse, and verify field observations.

**Components**: `ReportCard`, `SubmitReportFAB`, `VerificationBadge`, `ReportFilter`, `ReportForm`, `ImageUpload`, `LocationPicker`, `SeveritySelector`

**Features (List view)**: Filter by: category, severity, status (all/verified/pending), time
**Features (Submit form)**:
- Text description (required)
- Category: Flood / Drought / Infrastructure / Health / Food / Other
- Severity: Low / Medium / High / Critical
- Location: geolocation or map click
- Photo upload (Supabase Storage)
- On submit: immediate optimistic UI update + AI verification triggers asynchronously

**AI Verification**: FastAPI receives report → OpenAI analyzes text + image (vision) → returns confidence score 0–100% + suggested category correction + flagging if misinformation detected → Supabase updated → realtime update pushes to client

**Loading State**: Skeleton report cards
**Empty State**: "No reports in your area. Be the first to submit a field observation."

## 8.6 Action Impact Simulator (Modal / Feature within `/recommendations`)

**Purpose**: Scenario modeling — government officials compare outcomes before committing to a decision.

**Components**: `SimulatorModal`, `ScenarioInput`, `ComparisonPanel`, `ImpactMetric`, `SimulatorLoadingState`

**Features**:
- Text input: "What if we delay shelter opening by 24 hours?"

## Row Level Security (RLS) Policies

```sql
-- profiles: users can only read/update their own profile
CREATE POLICY "Users own profile" ON profiles
  FOR ALL USING (auth.uid() = id);

-- recommendations: users see recommendations for their role+region
CREATE POLICY "Users see relevant recommendations" ON recommendations
  FOR SELECT USING (auth.uid() = user_id OR region = get_user_region(auth.uid()));

-- community_reports: any authenticated user can read; only owner can update
CREATE POLICY "Anyone can read reports" ON community_reports
  FOR SELECT USING (auth.role() = 'authenticated');

CREATE POLICY "Owner can insert reports" ON community_reports
  FOR INSERT WITH CHECK (auth.uid() = user_id);

-- alerts: any authenticated user can read
CREATE POLICY "Anyone reads alerts" ON alerts
  FOR SELECT USING (auth.role() = 'authenticated');

-- conversations: only owner
CREATE POLICY "User owns conversations" ON conversations
  FOR ALL USING (auth.uid() = user_id);
```

```sql
CREATE INDEX idx_alerts_region_active ON alerts(region, is_active, created_at DESC);
```

| Task | Model | Justification |
|---|---|---|
| Recommendations | `gpt-4o` | Complex reasoning, structured outputs |

## Prompt Architecture

### System Prompt — Recommendations Engine
```
You are ActionLens AI, a calm and trusted disaster response advisor.
Your role is to provide ROLE-SPECIFIC, PRIORITIZED ACTION RECOMMENDATIONS.

User Role: {role}
User Region: {region}, {country}
Current Risk Data: {risk_data}

- Provide concrete, actionable steps only
- Calibrate recommendations to the user's role and capacity
- Express confidence as a numeric score 0-100
- Always provide evidence for each recommendation

- Priority: critical > high > medium > low
```

```
You are ActionLens AI — an intelligent mission control assistant for disaster response.
```

## Structured Output Schemas (Zod — enforced on FastAPI response)
```typescript
const RecommendationSchema = z.object({

  action: z.string(),

const ImpactSimulatorSchema = z.object({

    resourceDemand: z.string(),
    riskLevel: z.string()
  }),
  scenarioB: z.object({ /* same */ }),
```

## RAG Architecture
- **Knowledge Base**: Emergency preparedness guides, ICPAC historical reports, WHO disease outbreak protocols, FAO agricultural guidelines, UNHCR shelter standards
- **Storage**: `resources` table with `embedding vector(1536)` column (pgvector)
- **Indexing**: ivfflat index on embeddings
- **Retrieval**: Query → embed query with `text-embedding-3-small` → cosine similarity search → top 5 chunks → inject into prompt context
- **Chunk size**: 512 tokens, 50-token overlap
- **Re-ranking**: Simple cosine score threshold (> 0.75)

## Explainability Engine
Every recommendation includes a structured evidence chain:
```json
{
  "evidence": [
    { "label": "Rain Probability", "value": "91%", "weight": 0.35 },
    { "label": "Soil Saturation", "value": "82%", "weight": 0.25 },
    { "label": "ICPAC Alert", "value": "Level 3", "weight": 0.20 },
    { "label": "Historical Events", "value": "Similar 2024", "weight": 0.15 },
    { "label": "River Level", "value": "+2.3m threshold", "weight": 0.05 }
  ]
}
```
This is displayed visually in `ExplainabilityPanel` as a weighted bar chart with icons.

## Action Impact Simulator
- Input: natural language scenario OR structured (action type + time offset)
- GPT-4o uses Function Calling to extract scenario parameters
- Parallel API calls: model "act now" + model "alternative scenario"
- Returns: structured comparison + narrative recommendation

## Confidence Scoring
- Composite score from: data freshness (30%) + model certainty (40%) + evidence strength (30%)
- Displayed as circular arc indicator
- Color: >80% green, 60–80% amber, <60% red

## Caching & Cost Optimization
- Recommendations cached 30min per (role, region) combination in `recommendation_cache`
- Embeddings computed once, stored in Supabase — never re-computed for same text
- RAG retrieval results cached in memory (Next.js) for 10min
- Token-efficient prompts: structured data passed as JSON, not prose

## Rate Limiting
- Next.js API routes: 20 req/min per user (in-memory rate limiter)
- FastAPI: 100 req/min global (slowapi)
- Impact Simulator: 5 req/min per user (expensive endpoint)

## Fallback Behavior
- If OpenAI unavailable: serve last cached recommendations with staleness warning
- If FastAPI unreachable: return generic role-based static recommendations
- All fallbacks clearly labeled: "Showing last verified data from [timestamp]"
